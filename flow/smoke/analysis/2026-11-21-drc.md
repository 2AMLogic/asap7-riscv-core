# DRC residual-marker classification addendum: record 2026-11-21 (issue #225)

`flow/smoke/records/2026-11-21/` is the first smoke-flow run with the
flow-setting fixes that `flow/smoke/analysis/2026-11-05-drc.md` section
"Request fields that would change" named (and deliberately did not apply):
the M4-M7 track offsets moved to the deck's grid origin, the PDN straps
rebuilt on the deck's grids, and `options.flatten_layout: true` added to the
LVS request. This addendum classifies every marker that remains. It changes
no earlier evidence: `flow/smoke/records/2026-10-23/`, `2026-11-05/` and
`2026-11-15/` are byte-identical to `origin/main` (`git diff` is empty).

**ASAP7 is a predictive PDK; nothing here is fabricated or measured.** Every
number below is a tool result against the pinned deck
(`sha256:14f146f02cd731de3e0b59452eadfdab9c2c947724a219a1002a31b5e0f12d13`,
267 categories, re-verified by `run.sh` against the `spec/core.md` pin).

## What was applied in `flow/smoke/run.sh` (and one thing that was refused)

1. **`floorplan.tracks[]`**: M4/M5 `x/y_offset_um` 0.003/0.0 → **0.012**,
   M6/M7 0.0 → **0.016** — the values `2026-11-05-drc.md` verified against
   the deck's `ongrid` predicate and klayout-tools #4493 reports from an
   independent block. The record is the verification: 384 `M4.AUX.*` → 0.
2. **`power.straps[]` / `power.connects[]`**: explicit on-grid straps (M5
   `width_um` 0.216 so the wide-V4 bar applies, `pitch_um` 1.152 with
   centres at 12 nm mod 24; M6 `width_um` 0.288, `pitch_um` 1.152, centres
   at 16 nm mod 32) plus `connects[].ongrid: ["M3","M4"]` — the recipe of
   klayout-tools #4494, carried as explicit straps. `power.preset:
   "asap7sc7p5t"` was tried first and **rejected by the pinned klt 0.9.0**:
   the preset is gated to the unflavoured cell-library key
   `asap7sc7p5t_28` and refuses this flow's RVT overlay key
   `asap7sc7p5t_28_R` (name-binding disagreement, klayout-tools #7001,
   measured on this host during this issue's probe pass before the dated
   run). Explicit straps, not the preset, is the option this record lands.
3. **`lvs` request `options.flatten_layout: true`**: the 2026-11-05-lvs.md
   recipe. The new `lvs.json` reads `status: match`, `error_count: 0`,
   418/418 devices matched, against the same pinned LVS deck as before —
   closing the 19-error hierarchy-asymmetric compare of records 2026-11-05
   and 2026-11-15 at the flow level.

## Residual markers, each with a measured cause

### `V4.M4.EN.1` — 28 — and `V4.M5.EN.2` — 7 — PDN via stack, no request control

> Table 3.15.1: min enclosure of V4 by M4 (EN.1) / M5 (EN.2) on two opposite sides 11 nm

All 35 markers are rectangles **exactly 216 nm × 24 nm** — the M5 strap
width and the M4 minimum wire height. Their x-extents fall in five columns
centred at x = 1500, 2076, 2652, 3228, 3804 nm (576 nm apart: VDD and VSS
straps alternating at half the 1.152 µm pitch, so every strap column of the
core is covered), and every y-extent is a 24 nm-tall M4 wire whose lower
edge sits on the new M4 track grid (1056, 1344, 1584 … nm, all multiples of
48). The shape is the M4 landing segment under an M5 strap: the PDN
M2→M5/M5→M6 connect stack drops a V4 cut array as wide as the 216 nm strap
onto a minimum-width M4 wire, and a 24 nm wire cannot enclose a wider cut
row by 11 nm on two opposite sides. No `power.*` request field reaches this
geometry — this is the M2-M5 via-stack residual the `asap7sc7p5t` preset
documents with the same rule ids (klayout-tools #4499, #6030, #6180); the
open fix request is **klayout-tools #6909**, which this layout's counts
(28 × `V4.M4.EN.1`, 7 × `V4.M5.EN.2`, with explicit on-grid straps rather
than the preset) were posted to as a datapoint. Not waived, not filtered,
not patched: there is nothing in this repo to do about them.

### `SDT.ACTIVE.AUX.2` — 6 — deck + pinned cell library (unchanged from 2026-11-05)

> Table 3.8.1: SDT (not interacting with SRAMDRC) horizontal edges must coincide with ACTIVE horizontal edges

The same six markers `2026-11-05-drc.md` section "SDT.ACTIVE.AUX.2 — 6"
classifies, re-measured on the new placement: two per `BUFx4_ASAP7_75t_R`
instance, at the same cell-internal places — the horizontal edges at cell
y = 108 and y = 162 over x 42…66. The DEF places the three CTS instances at
(1836, 1350) FS, (2538, 1080) N and (1458, 3510) FS; each instance's two
markers sit exactly at its origin plus those cell coordinates (e.g. 1458+42
= 1500 … 1458+66 = 1524, y 3510+108 = 3618 and 3510+162 = 3672). No router
geometry is involved. `BUFx4` is on klt's shipped-cell deviation list
(`asap7_rules.SHIPPED_CELL_DEVIATION_RECORDS`); a disclosed exception for
T1 item 3 is a decision record that **#29 owns** — stated here, not waived.

### `M1.S.4` — 1 — and `M1.S.5` — 2 — router via-pad tips

> Table 3.12.1: min tip-to-tip M1 spacing 31 nm (S.4 both edges < 24 nm; S.5 one edge 24..36 nm, other < 24 nm)

Three tip-to-tip markers on top-level router M1 (first violations: bbox x
3281…3303 nm, y 1235…1253 nm for `M1.S.4`; x 1773…1800, y 2851…2864 and x
1989…2016, y 1989…2009 for `M1.S.5`), at the protruding pad tips of
router-inserted via stacks — the failure mode klayout-tools #4508 tracks
(trimming protruding `VIA_*` M1 pad tips; follow-up to #4495, which
`2026-11-05-drc.md` already linked for router-inserted landing-pad
geometry). The router's own DRC reports 0 on the same GDS. Not waived.

## Reproduction

Same one command as 2026-11-05, on the committed GDS:

```bash
sha256sum <site-packages>/klayout_tools/decks/asap7.drc
# 14f146f02cd731de3e0b59452eadfdab9c2c947724a219a1002a31b5e0f12d13
klayout -b -r asap7.drc \
  -rd input=flow/smoke/records/2026-11-21/layout/counter.gds \
  -rd report=/tmp/repro.lyrdb
```

yields 44 items with exactly the per-rule counts above. The record's
markers carry `polygon`/`source_cell`/`source_path` null (flat check), so
every attribution above was re-derived from the record's bboxes plus the
DEF and the strap arithmetic, the same method as 2026-11-05.
