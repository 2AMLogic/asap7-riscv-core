# 0019 — Attestation retention: what must survive a re-attestation

**Status:** proposed 2026-11-19, awaiting operator ratification. Implements the operator's ruling on issue #89
(option (a), 2026-11-18), which is his reading of ruling r7-q12 (issue #65). This record is not self-ratified; until
the operator ratifies it, `spec/decisions/0012-shared-archtest-module-and-item9-reattestation.md` is still the adopted
text and this record is a proposal.

**Problem.** `spec/decisions/0012-shared-archtest-module-and-item9-reattestation.md` states the append-only rule as
"results and attestations are never deleted or rewritten". The documented item 10 recipe in
`.github/workflows/signoff.yml` regenerates `evidence/item10.json` in place, which reads as a rewrite. Ruling r7-q12
says: "results and attestations are append-only; inputs, generators and superseded tooling are not. A removal PR must
(a) add a superseding record or attestation wherever one cites a removed file, (b) re-point every citation, and (c) for
regenerable inputs, record the generator command plus a byte-for-byte regeneration check in the PR. Result and report
files are never deleted." Its operative verb is delete, in a removal-PR frame; "or rewritten" has no counterpart in it.

**Decision.** The rule, restated in full:

1. **Removal.** Results and attestations are never deleted. A PR that removes an input, a generator or a superseded
   tool that a result or attestation cites must (a) add the superseding record or attestation, (b) re-point every
   citation, and (c) for regenerable inputs, record the generator command and a byte-for-byte comparison in the PR.
2. **Tool-produced envelopes.** An attestation envelope generated by a pinned tool may be regenerated in place when the
   superseded envelope reproduces byte-for-byte from the tree at its own commit with the pinned tool. Git history then
   holds the superseded record completely; no copy under `evidence/records/` is owed. Never hand-edit an envelope
   (`spec/decisions/0009-item-10-repo-hygiene-attestation.md` stands).
3. **Non-reproducible records.** A record that cannot be reproduced from the tree, such as a simulation or measurement
   log, is retained under `evidence/records/` (or its existing dated results directory) when superseded.
4. **Explicit orders still apply.** Where a ruling or decision orders retention specifically, it applies even when
   regeneration is possible. Item 9's retain-first procedure
   (`spec/decisions/0014-item-9-check-gate-and-lib-sh-attestation.md`, originating in 0012) is unchanged:
   copy the committed `evidence/item9.json` to `evidence/records/item9-<date>.json`, then regenerate.

**Supersession.** For item 10, this record is the successor to `spec/decisions/0009-item-10-repo-hygiene-attestation.md`
on retention (0009 is silent on it; its "tool-produced, never hand-edited" requirement stands). It supersedes the
"or rewritten" clause of `spec/decisions/0012-shared-archtest-module-and-item9-reattestation.md`. That file is not
edited; the rest of it, including the item 9 retention it materialised, stands. A committed record is not rewritten.

**Evidence: byte-for-byte regeneration at a historical commit.** Run 2026-11-19 in a clean detached checkout of
`ac62178ba5d70d5b9110bedd402a724b8fe14541` (an item 10 re-attestation that predates 0012), with `klayout-tools==0.8.0`,
Python 3.12.16, Icarus 13.0, Verilator 5.050 and cocotb 2.0.1. The run is the one recorded in issue #89 (its Test
Plan), not a fresh run taken for this record. Both local harness commands ran, including the negative
control's intentional assertion failure. All 6 checks passed. From the checkout root, output outside the tree:

```sh
fresh=$(mktemp)
uvx --python 3.12 --from 'klayout-tools==0.8.0' klt signoff \
    --attest 10 --inventory attest/item10.json -o "$fresh" &&
    cmp evidence/item10.json "$fresh" &&
    sha256sum evidence/item10.json "$fresh"
```

`cmp` exited 0. Both files were 2,224 bytes with SHA-256
`adfd62bbbfba2e7d6022d585f98fdbe16ec1191a7571027a54adbca4abe1fe4b`. The workflow's `--check` skips local-only command
execution, so a full generation is the proof. If a properly provisioned replay ever fails to reproduce an envelope,
that envelope is not covered by rule 2 and must be retained under rule 3.

**Not changed.** No historical backfill or waiver (nothing on `main` violated the rule as scoped here), no change to
inventories or klt pins, and no new CI enforcement.
